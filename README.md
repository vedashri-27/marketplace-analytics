# Marketplace analytics (simulated)

A personal project where I built a fake online-experiences marketplace (think
city tours, attraction tickets, day trips) and then did the kind of analytics
work I'd do on a real one: model the warehouse, write the SQL, run the numbers,
automate the weekly report, and put a dashboard on top.

I built it to practise end-to-end analyst work on a two-sided marketplace —
GMV vs take rate, a session-to-booking funnel, marketing ROAS/CAC, cohort
retention, supplier economics, dynamic pricing, and an A/B test — rather than
yet another single-CSV notebook.

The data is synthetic and generated by a seeded script, so none of the numbers
are real, but the methods are the same ones you'd use on production data.

## A few things I found

- **Display ads lose money** (0.58x ROAS, ~$94 CAC). Affiliates (2.0x) and Paid
  Social (1.8x) are the ones to scale. See `sql/02_growth_marketing.sql`.
- **Mobile checkout is the biggest product problem** — it converts ~25% worse
  than desktop and it's ~62% of traffic. The Scenario Simulator tab in the
  dashboard sizes the upside of fixing it.
- **The checkout_v2 A/B test is a real win**: +16.6% relative lift, p < 1e-10
  (two-proportion z-test in `python/03_analysis.py`).
- **Supplier concentration is a risk** — ~60 of 134 active suppliers drive 80%
  of GMV.
- Dynamic pricing is pulling its weight (~$161k incremental GMV, +3.3%).

More detail in `docs/INSIGHTS.md`. The reasoning behind some of the modelling
choices is in `docs/DECISIONS.md`.

## Running it

On Mac/Linux (or Git Bash on Windows):

```bash
pip install -r requirements.txt
./run_all.sh
```

On Windows PowerShell, run the steps directly:

```powershell
pip install -r requirements.txt
python python/01_generate_data.py
python python/02_run_sql.py
python python/03_analysis.py
python python/05_build_dashboard.py
python python/04_weekly_report.py
```

Then open `dashboard/index.html`. It's seeded, so you'll get the same numbers I did.

Optional — build the warehouse with dbt (runs on DuckDB over the CSVs):

```bash
cd dbt
export DATA_DIR=$(cd ../data && pwd)     # PowerShell: $env:DATA_DIR = (Resolve-Path ..\data)
dbt build --profiles-dir .
```

## Notes / things I'd still do

- The marketing attribution is last-touch, which over-credits lower-funnel
  channels. Multi-touch would be the honest next step.
- The "health index" weights are my own judgement (see `docs/DECISIONS.md`) —
  useful as a single number, but not something I'd ship without a team agreeing
  on the weights.
- Would like to add a proper price-elasticity model instead of the rule-based
  dynamic pricing in the generator.
